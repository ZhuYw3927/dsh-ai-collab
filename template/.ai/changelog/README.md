# `.ai/changelog/` — 版本级变更记录

> 面向人的**结构化文档**入口，由 `AGENTS.md §6` 路由。
> 与 `.ai/log.jsonl` 的分工：`log.jsonl` 是逐次操作的流水（给 AI），本目录是版本级的结论（给人）。

## 1. 建议文档清单（按需创建，保留前缀序号）

| 文件 | 内容 |
|---|---|
| `README.md` | 本文件：版本一览、目录导航、Flash 布局等总览 |
| `01_<模块>_修改记录.md` | 按主题分组的改动清单（文件位置 / 原因 / 关联补丁） |
| `02_<模块>_修改记录.md` | 多工程时按工程拆分（如 APP / IAP） |
| `03_问题排查日志.md` | 时间线：现象 → 根因 → 处理 → 上板结果（**弯路也要记**） |
| `04_构建产物与验证.md` | 编译结果、产物路径、烧录地址、实测数据、已知限制 |
| `05_回滚与归档.md` | 备份/归档目录、补丁索引、回滚步骤 |
| `06_改动文件清单.csv` | 机器可读：`工程,相对路径,主要改动,相关补丁` |
| `07_<协议或接口>速查.md` | 实测验证过的协议/接口要点（帧格式、命令、约束） |
| `patches/` | 可复现每一步改动的补丁与引擎 |

## 2. 写作规则

1. **一条改动一行**：`# | 改动 | 文件（行） | 原因 | 补丁`；
2. 行号标注"当前文件位置"，并注明会随编辑漂移；
3. 排查日志用"现象 / 根因 / 处理 / 结果"四段式，弯路也要写（避免后人重踩）；
4. 实测数据放表格（场景 / 时长 / 帧数 / 错误数 / 结论）；
5. 引用补丁写文件名，补丁本体放 `patches/`；
6. 不写"正确但无用"的流水账，重点记**决策依据**与**踩坑点**。

## 3. 补丁归档

- `patches/` 存放可复现每一步改动的补丁与引擎；
- 引擎 `apply_patches.ps1` 的格式：`@@FILE` / `@@OP RANGE|TEXT` / `@@OLD`+`@@NEW` / `@@END`；
- 同一文件内多段补丁按起始行**降序**应用，避免行号漂移；
- 应用前 `-DryRun` 预演，应用后**回读校验**（文本替换类补丁可能吞掉条件行）。

## 4. 与其它记录的关系

| 记录 | 用途 | 更新频率 |
|---|---|---|
| `.ai/status.json` | 当前状态（覆盖式），新工具 10 秒接手 | 每次阶段性工作 |
| `.ai/log.jsonl` | 跨工具交接的流水（追加式） | 每次阶段性工作 |
| `.ai/changelog/` | 版本级根因 / 验证 / 已知限制（权威） | 每个版本 |
| 工程内 `readme.txt` | 对外修改历史 | 每次发版 |
| 版本库 `log` | 文件级入库变更 | 每次提交 |

## 5. 与版本库

- 本目录**不纳入版本库**（属本地协作与过程记录）；
- 需要长期留存的结论（协议约定、接口变更）应同时体现在工程 `readme.txt` 或代码注释；
- 迁移/改名后在本文件末尾追加"路径说明"，列出历史路径与当前对应关系。
