# dsh-ai-collab

A DeepSeek Harness bundle that gives every AI tool in a repository the same project memory (visual introduction: <https://ZhuYw3927.github.io/dsh-ai-collab/>):
one `AGENTS.md` entry file and one hidden `.ai/` folder holding an append-only work log,
a current-state snapshot, and version-level change notes.

## Where this document is used

This long-form manual ships inside the package. The DSH store detail page renders `README.md`
instead — the `meta.detail` pointer was removed from both locales in 0.7.1 — so the store shows
the screenshot, feature notes and limitations from one document.

## Why

Every new session spends its first minutes rediscovering the build command, the read-only
folders, and what the previous session changed. `dsh-ai-collab` turns that into two plain
files that any tool can read: `AGENTS.md` for facts, `.ai/log.jsonl` for history.

## What it adds

| Capability | Detail |
|---|---|
| Eight tools | `ai_status`, `ai_log`, `ai_check`, `ai_board`, `ai_init`, `ai_discipline`, `ai_handoff`, `ai_plan` |
| Auto-adoption | On `session/created` (`autoInit: true`) run `ai-ensure` in non-temp directories: scaffold when missing, upgrade when the template changed, refresh the board when stale |
| Zoned `AGENTS.md` | A `generated` zone (routing, permissions, commands, §8 discipline list) replaced on upgrade, and a `user` zone (project facts, sampling data, analysis methods, decisions) preserved byte-for-byte |
| Disciplines | Global modules in `$DSH_HOME/disciplines/` (migrate/toggle via `ai_discipline`) and project rules in `.ai/disciplines/`; enabled project rules are inlined into §8, disabled ones only listed |
| Handoff | `.ai/SESSION_BOOT.md` carries status, recent records, disciplines and an inheritance prompt; regenerated by `ai_log` / `ai_init` / `autoInit` |
| Protected files | An `AGENTS.md` without zone markers is treated as project-owned and never rewritten; the rendered reference goes to `.ai/AGENTS.generated.md`; rewrites are atomic and backed up |
| Task list | `.ai/log.jsonl` drives a three-section `.ai/TASKS.md` (plan → checklist → risks → log) and a self-contained root `TASKS.html` dashboard; `refreshTasks` auto-creates `.ai/tasks-enabled` on first write |
| Cross-project board | When a sibling `.ai/board.md` exists, the board is refreshed after a record is written; `dashboard.html` scans all projects with red-highlighted blocker rows |
| Plan & risk tracking | `.ai/plan.json` stores goals, checklists and risks; active risks merge into `status.json` → `blockers` on every `ai_log`; managed via `ai_plan` (show / set / done) |
| Concurrency | `lib/lock.js` cross-process lock + `lib/atomic.js` temp/fsync/rename; `status.json` has a `rev`; PowerShell `llm.ps1` mirrors both |

## Install

- **Plugin Manager (recommended):** Plugins → Add plugin → select this package directory.
- **CLI:** `dsh plugin --profile <profile> add <package path or npm name>`
- Restart DSH once; every session in the profile then exposes the eight tools.

## Configuration

| Key | Default | Meaning |
|---|---|---|
| `autoInit` | `false` | Adopt/refresh the session working directory on session creation |
| `maxTail` | `10` | Number of recent records returned by `ai_status` |
| `initScript` | packaged `ai-ensure.ps1` | Override the adoption script (debugging) |

Values are normalised and invalid values are reported as warnings in
`$DSH_HOME/logs/ai-collab-config.log`; they are never silently used as-is.

## The `.ai/` layout

```
<project root>
├─ AGENTS.md              generated zone + user zone
├─ TASKS.html             self-contained dashboard-style task view (auto-regenerated)
├─ (root policy: only AGENTS.md + HTML pages live at the top level)
└─ .ai/
   ├─ llm.ps1 / llm.cmd   status / tail / add / check / board / doctor / tasks
   ├─ log.jsonl           append-only, UTF-8 without BOM, LF
   ├─ status.json         current-state snapshot (overwritten, `rev` increments)
   ├─ plan.json           structured plan: goals, checklists, risks
   ├─ PLAN.md             rendered plan`n   ├─ TASKS.md            three-section markdown archive (plan → checklist → risks → log)
   ├─ SESSION_BOOT.md     cross-session handoff packet
   ├─ disciplines/        project discipline registry + rules/
   ├─ LOG_FORMAT.md / SECURITY.md / schema/log.schema.json
   ├─ changelog/           version-level notes and patches
   ├─ entries/             forwarding masters for Claude Code / Gemini CLI
   ├─ docs/                project documents (external intro / maintenance notes)
   ├─ scripts/             maintenance scripts
   ├─ dist/                release artifacts
   └─ _archive/
```

A record is one JSON object per line:

```json
{"id":"20261117T062049123-ab12cd","ts":"2026-11-17T14:20:49+08:00",
 "tool":"deepseek-harness","actor":"ai","action":"fix","status":"ok",
 "summary":"...","files_modified":["src/a.c"],"verification":"rebuild 0/0"}
```

## Safety

- The log is append-only; corrections are new records (`action: "correction"`).
- Adoption writes only into the workspace, never into system or temp directories.
- The plugin performs no network requests and stores no credentials.
- Task rendering runs inside the plugin; it never executes a workspace-provided script.
- Writes are atomic (temp + `fsync` + rename) and record/status updates take `.ai/.log.lock`;
  PowerShell `llm.ps1` uses the same lock protocol. This is cooperative, not an OS guarantee.
- `install.ps1` backs up `AGENTS.md` to `.ai/backups/` (last 10) before changing it.

## Compatibility

- DSH `0.2.1+` (tested on `0.2.2-rc.3`).
- Node.js `>= 20` (the bundled Electron Node works).
- **Windows 10/11 only for now.** Scaffolding (`ai_init`, `autoInit`) runs Windows PowerShell 5.1;
  the package declares `"os": ["win32"]`. The read-only tools and task rendering are
  platform-neutral, but macOS/Linux are not supported or tested yet.

## Known limitations

- The scaffolding scripts are Windows-only; other platforms get the read-only tools.
- The bundle declares no display icon fallback for hosts older than the locale/meta support.
- A legacy `AGENTS.md` without zone markers is frozen by design; migrate explicitly with
  `install.ps1 -ForceAgents` (moves old content into the user zone) or `-ResetAgents`.
- Global discipline toggles require a prior `ai_discipline global-migrate`; they rewrite
  `$DSH_HOME/AGENTS.md`, and a global module cannot be disabled for a single project.
- §8 of a project `AGENTS.md` refreshes on the next `ai-ensure` / `install.ps1` render.
