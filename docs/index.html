01 · 问题

每个新会话，都在重新认识同一个项目

多 AI 工具协作时，最贵的成本往往不是写代码，而是让每个新会话重新理解项目——构建命令、烧录地址、只读目录、上次改到哪、为什么这样改。

02 · 机制

一个入口，一层协作层

它不改变工程结构，只在项目根增加两样东西。AGENTS.md 负责「说清楚」，.ai/ 负责「记下来」。

AGENTS.md

唯一入口

所有工具开工先读：项目事实（构建、烧录、只读目录、编码约定）与固定动作（开工读什么、收工写什么）。纯文本、可 diff、可评审。

  • DSH、Cursor 3.x、Copilot 原生读取
  • Claude Code / Gemini 可一行转发
  • 分 generated 与 user 两区维护

.ai/

协作层

追加式日志、当前状态快照、版本级变更、schema 与归档。所有写入经由 .ai\llm.cmd 或 8 个原生工具，编码与格式由脚本保证。

  • log.jsonl 只追加，不改写
  • status.json 覆盖式，10 秒接手
  • changelog/ 存根因、数据与补丁
  1. STEP 1开始会话任意工具进入项目
  2. STEP 2读 AGENTS.md事实、约束、固定动作
  3. STEP 3status + tail当前阶段与最近十条
  4. STEP 4执行并 add一行记录，带验证结果
  5. STEP 5check 后交接下一个工具从文件接手

与语言、框架、IDE 无关：嵌入式固件、桌面应用、脚本仓库、文档工程共用同一套协议。

03 · 统一进度

同一份事实，同一份历史

工具可以换，入口不变。每个工具开工前读同一份快照，收工后写同一条流水；人也不例外。

工具接入方式参与方式
DSHBundle 安装，8 个原生工具ai_status / ai_log / ai_check 直接读写
Claude Code用户级 CLAUDE.md 转发，或 entries -Publish读 AGENTS.md，用 llm.cmd 记录
Cursor / Copilot原生读取 AGENTS.md继承项目事实与纪律
Codex / 其他 CLI任意 shell 调用 .ai\llm.cmdstatus / tail / add / check
人同一条命令tool: human，决策与验收也入账
01 开工≈ 10 秒

先读状态

status 与 tail -N 10：当前阶段、焦点、阻塞、下一步，以及最近十条记录。

02 收工1 条记录

追加流水

add 自动生成 id 与时间戳，刷新 status.json，并在需要时刷新看板与 TASKS.md。

03 提交前强制

校验记录

check 检查必填字段、枚举、时区、时间单调与 id 唯一，可选扫描敏感信息。

换工具不换进度，换会话不换上下文。

04 · 本地记录

记录留在本地，半年后还能追溯

聊天记录会消失，仓库里的文件不会。每次工作被压成一行可校验的 JSON，「当前状态」与「版本级细节」分开存放。

Append-only · log.jsonl

只追加，不改写

UTF-8 无 BOM、LF、一行一个 JSON 对象。写错就追加一条 correction，用 corrects 指向原记录；历史行永不修改或删除。

Snapshot · status.json

覆盖式状态快照

phase、focus、blockers、next、last_log。新工具先读这一份，不必翻完整本流水。

Changelog · changelog/

版本级细节

根因、实测数据、补丁与已知限制。日志里的 summary 用 refs 指过去，不把单条记录撑大。

Validate · ai_check

结构可校验

必填字段、枚举、时区、ts 单调、id 唯一；超过 2 MB 或每季度归档到 _archive/，历史仍可检索。

{
  "id": "20261120T013921289-a3a5b4",   ①
  "ts": "2026-11-20T09:39:21+08:00",  ②
  "tool": "deepseek-harness",
  "actor": "ai",
  "action": "fix",                   ③
  "status": "ok",
  "summary": "修正 DMA 环形缓冲边界，rebuild 0/0",  ④
  "files_modified": ["src/uart_dma.c"],
  "verification": "rebuild 0/0, Code=124476",  ⑤
  "refs": [".ai/changelog/2026-11-20-uart-dma.md"]
}
  • ①唯一 id，供 correction 引用
  • ②ISO-8601 带时区，时间必须单调
  • ③status 五态；blocked / failed 必填 issue
  • ④一句话结论：做了什么 + 结果
  • ⑤怎么验的，以及细节在哪
一行记录谁、何时、做了什么
状态快照现在到哪、卡在哪
版本变更为什么、怎么验证
季度归档历史仍可检索

目标只有一个：任何时候都能回答——谁做的、改了什么、怎么验的、下一步是什么。

工作记录不出工作区。插件不发起网络请求、不写注册表、不接触凭据；敏感值放 .ai/private/，文档只写键名。任务清单在插件进程内渲染，克隆来路不明的仓库并记录日志，也不会执行仓库里的脚本。

05 · 分区设置

模板管纪律，项目管事实

AGENTS.md 被两条标记切成两个区。插件升级时只重写 generated 区，项目事实与区外内容逐字节保留。

AGENTS.md generated + user
generated 区 · §2–§7 模板维护 · 升级时重写

开工 / 收工固定动作、目录与权限表、构建与验证、硬性约束、领域文档索引、多工具入口。

  • 开工 / 收工固定动作
  • 目录与权限表
  • 构建与验证方式
  • 硬性约束与编码规则
  • 领域文档索引
  • 多工具入口与转发

<!-- dsh-ai-collab:generated:end -->   <!-- dsh-ai-collab:user:start -->

user 区 · §1 及之后追加 项目维护 · 逐字节保留

项目名、根目录、MCU / 工具链、版本控制、日志位置，以及采样数据、分析方法、硬件与协议约束、决策记录。

  • 项目名与根目录
  • MCU / 工具链
  • 版本控制与日志位置
  • 采样数据与采集过程
  • 硬件 / 协议约束
  • 决策与验证结论

实际文件由 HTML 注释标记分隔；上方两个区之间同时出现 generated 区的结束标记与 user 区的开始标记，文件末尾是 user 区的结束标记。

分区规则

场景行为
重渲染范围只替换 generated 区；user 区与区外内容逐字节保留
其它状态文件placeholders.json / log.jsonl / status.json 一律不动
无分区标记的文件视为项目自有文件并冻结（含旧格式单行标记）；参考渲染只写 .ai\AGENTS.generated.md
显式迁移-ForceAgents：旧内容整体迁入 user 区，不删除；-ResetAgents：丢弃旧内容，破坏性

分区也发生在项目之间：每个仓库的 .ai/ 只属于自己；兄弟项目共享的 board.md 只读汇总，不反写任何项目的记录。

升级不再意味着「重新生成一份 AGENTS.md，再手工补回项目事实」。同一份 generated 区里还有 §3 权限表，把「哪些路径可写」也变成可评审的约定；user 区则由项目长期维护。

06 · 全局纪律

全局纪律，随每个会话加载

纪律现在由插件管理，不再靠手抄。全局纪律驻留在 $DSH_HOME/AGENTS.md，DSH 在每个会话无条件注入；ai_discipline global-migrate 把它拆成 8 个可独立开关的模块（g0.md…g7.md），之后 global-disable g7 这样一条调用就能让某节纪律从提示词里真正消失。

01 · 安装$DSH_HOME/AGENTS.md跨项目纪律，一份文件
02 · 注入每个新会话DSH 启动时自动加载
03 · 第 0 步ai-ensure接入 / 升级 / 刷新，幂等
04 · 落地项目 AGENTS.md + .ai/事实与记录各归其位

全局文件只放跨项目纪律，没有任何项目事实。项目事实留在 <项目根>/AGENTS.md。编辑全局文件对下一次请求立即生效，无需重启；插件代码升级才需要重启 DSH。

能做什么、不能做什么：可以全局停用某一节纪律，也可以给单个项目追加更严的规则；但不能只对某个项目卸载全局纪律——DSH 注入全局文件是无条件的，项目级只能「加」不能「减」。

00

第 0 步 · ai-ensure

每个会话先保证接入与同步：缺骨架则生成、模板过期则升级、看板过期则刷新。临时或系统目录返回 not-project，不强行接入。

01

先对齐，再动手

动手前给出本轮目标、待定项、方案与取舍；确认后执行。纯只读查询例外。

02

日志归属与看板边界

详细记录只留在各自项目的 .ai/；跨项目看板只读汇总，禁止反写项目内容。

03

默认只读与权限确认

工程文件默认只读；写未列出的路径，先说明原因与影响范围，确认后更新权限表再动手。

04

三步工作法

status + tail 开工，add 收工，check 校验。没写记录 = 这件事没做完。

05

事实与模板同步

generated 区归模板，user 区归项目；重渲染只替换 generated，事实逐字节保留。

06

硬性边界

临时目录、只读目录、工作区之外不接入；凭据、内网地址、客户信息不进日志。

07

记录质量

summary 写「做了什么 + 结果 + 验证方式」；根因、数据与补丁放 changelog，用 refs 指过去。

层级文件放什么维护者
用户级$DSH_HOME/AGENTS.md跨项目纪律，无项目事实用户 / 模板
项目级<项目根>/AGENTS.md项目事实 + 纪律路由generated 模板 + user 区
证据级.ai/log.jsonl 等每次工作的流水与验证所有工具与人
 
# 首次：把已有的全局 AGENTS.md 拆成可开关的模块（先备份，原文逐字节保留）
ai_discipline action:global-migrate

# 日常：全局模块开关，改完立即重渲染 $DSH_HOME/AGENTS.md
ai_discipline action:global-list
ai_discipline action:global-disable id:g7
ai_discipline action:global-enable  id:g7

# 项目级：只对这个项目追加更严的规则，正文会内联进 AGENTS.md §8
ai_discipline action:add id:no-force-push title:"禁止强推主干" `
  body:"推送前先确认远端状态；禁止 git push --force 到 main。"
ai_discipline action:disable id:no-force-push   # 只保留表行，不再约束

§8 是自检点。项目 AGENTS.md 的 generated 区里有一张纪律清单：全局行 G0…G7 只做索引（正文在全局文件里），项目行 P-* 的正文按「启用」内联。规则文件是纯 Markdown，人和工具都能改；ai_check 会报告漂移——启用了却没内联、停用了却还内联、注册表读不出来。

07 · 交接与并发

新会话先读一份「接棒提示词」

原始日志是事件流，不适合当成开场白。插件维护一份 .ai/SESSION_BOOT.md：当前状态、最近记录、纪律清单、必读顺序，以及「读完请输出继承摘要」的指令。ai_log、ai_init 与自动接入都会重写它，ai_handoff 负责读取、重建和生成可粘贴的继承提示。

01 · 读取SESSION_BOOT.md接棒提示词与必读顺序
02 · 加载status.json + log.jsonl状态快照与最近流水
03 · 汇报继承摘要5–8 行，事实全部来自文件
04 · 开干本轮任务接着已有进度，不重新摸一遍
# 新会话开场：读接棒提示词（文件缺失时先生成再返回原文）
ai_handoff action:read

# 或者直接要一段可粘贴给新会话的继承指令
ai_handoff action:inherit

# 收工写记录时会自动重建 SESSION_BOOT.md
& .ai\llm.cmd add -Tool deepseek-harness -Action fix -Status ok -Summary "…"

多会话同时写，不会写坏文件

风险做法结果
两个会话同时写日志.ai/.log.lock 跨进程锁，append 与状态更新在同一临界区12 个进程并发写入 → 12 条记录、id 全唯一、rev=12
写到一半被读到临时文件 + fsync + rename 原子替换（对占用/权限错误退避重试）读者只会看到旧版或新版，没有半截文件
TASKS.md 被并行覆盖.ai/.tasks.lock 内整份重渲染清单始终与日志一致
AGENTS.md 改坏原子写 + 写前备份到 .ai/backups/（保留最近 10 份）可回滚；-ResetAgents 也有备份
状态快照丢更新status.json 增加自增 rev，写入在锁内完成rev 可作为「有没有丢写」的快速判断
纪律与实际渲染不一致ai_check 审计 §8 漂移启用未内联 / 停用仍内联 / 注册表损坏都会报错

边界要说清：这是插件与 .ai/llm.cmd 之间的协作锁，不是操作系统级保证。用编辑器或别的脚本直接改这些文件，仍然可以绕过锁；initScript 是可信配置，不要指向不可信代码。

三条命令，开始交接

安装一次，之后每个会话只重复三个动作：读状态、干活、写记录。

A

推荐。选择本包绝对目录即可。

plugin_manager
  action: install_bundle
  target: <包绝对路径>
B

命令行

npm 包名或本地目录均可。

dsh plugin --profile <profile> add dsh-ai-collab

# 或本地目录
dsh plugin --profile <profile> add "<包绝对路径>"
C

profile patch

仅开发调试；生产安装走 bundle。

- insert:
    - id: ai-collab
      name: dsh-ai-collab
      config:
        autoInit: true

安装后重启 DSH；profile 内所有会话都会出现 8 个工具。首次进入某个项目时，先调用 ai_init（或把 autoInit 设为 true）生成 .ai/ 与 AGENTS.md，之后按下面的动作循环。若包只进了依赖、未进 dsh.profile.bundles，需要手动补一行。

# 开工：同步并读状态（约 10 秒）
& .ai\llm.cmd status
& .ai\llm.cmd tail -N 10

# 收工：追加一条记录，然后校验
& .ai\llm.cmd add -Tool deepseek-harness -Action fix -Status ok `
  -Summary "修复 UART DMA 丢包，验证：rebuild 0/0" `
  -Verification "rebuild 0/0, Code=124476"
& .ai\llm.cmd check

ai_handoff跨会话交接摘要

常用命令

命令作用何时用

  • 1脚手架仅 Windows。macOS / Linux 返回 unsupported-platform；只读工具与任务渲染本身不依赖平台。
  • 2尚未导出 Config schema。配置在进程内归一化，非法值写入 ai-collab-config.log，不会静默沿用。
  • 3旧 AGENTS.md 被冻结。无分区标记的文件不会自动升级，需显式 -ForceAgents 或 -ResetAgents。
  • 4看板依赖目录布局。仅当兄弟项目共享父级 .ai\board.md 时生成跨项目看板。
  • 5生效时机不同。插件代码改动需重启 DSH；全局 AGENTS.md 编辑对下一次请求立即生效；项目 §8 纪律清单在下次 ai-ensure 渲染时刷新。
  • 6全局纪律只能整体开关。停用/启用会重渲染 $DSH_HOME/AGENTS.md，且必须先 global-migrate；不能只对某个项目停用某节全局纪律。
  • 7锁是协作式的。插件与 .ai/llm.cmd 遵守同一套锁协议；外部编辑器直接改文件仍可能绕过。单个项目日志建议不超过 2 MB 并及时 archive。

10 · 结语

它不发明新的工作流，只是让「交底、记账、校验」留在仓库里。

于是工具可以换、会话可以断、维护者可以更替，而项目的进度与判断依据不会丢。这就是 dsh-ai-collab 的全部野心：把一次性的会话成本，变成可继承的项目资产。
