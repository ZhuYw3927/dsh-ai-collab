# dsh-ai-collab

[![ci](https://github.com/ZhuYw3927/dsh-ai-collab/actions/workflows/ci.yml/badge.svg)](https://github.com/ZhuYw3927/dsh-ai-collab/actions/workflows/ci.yml)

A [DeepSeek Harness](https://github.com/deepseek-ai) bundle that adds a **project-agnostic AI collaboration layer** built around two ideas:

- `AGENTS.md` — the single entry file at the project root (facts: build/flash commands, constraints, read-only dirs);
- `.ai/` — one hidden folder holding an append-only work log, a current-state snapshot, a JSON schema and archive.

The point: any AI tool working in the repo (DSH, Claude Code, Cursor, Copilot, Codex) reads and writes the same progress, instead of rediscovering the project every session.

> **Visual introduction (中文):** <https://ZhuYw3927.github.io/dsh-ai-collab/>

> Status: **0.6.0, experimental**. Published on npm as [`dsh-ai-collab`](https://www.npmjs.com/package/dsh-ai-collab) and listed in the community plugin market — see [Known limitations](#known-limitations).

## What's new in 0.6.0

- **Plan & task management.** The new `ai_plan` tool (`show`/`set`/`done`) stores a structured plan
  in `.ai/plan.json`: goals, checklists (with done/undone toggles), and risks (each with a
  severity badge, a mitigation, and an active/resolved flag). Active risks are auto-merged into
  `status.json` → `blockers` so they surface in every status readout.
- **`TASKS.md` is now three-section** (plan → checklist → risks → log) and also rendered as
  **`TASKS.html`**, a self-contained dashboard-style page with status badges and risk colour
  coding. The `.ai/tasks-enabled` marker is no longer needed — `refreshTasks` creates it
  automatically on first use.
- **Cross-project dashboard**: `F:\MyProject\.ai\dashboard.html` is generated after every
  `ai_log` and `ai_init`. It scans all sibling projects, highlights rows with active blockers in
  red, and renders a sparkline bar of recent record counts per project.
- **Workspace layout cleaned**: root directory reduced to `AGENTS.md` + `TASKS.md` +
  `dsh-ai-collab.html`; everything else now lives under `.ai/docs/`, `.ai/scripts/`,
  `.ai/dist/` or `.ai/market/`. A stray `dsh-ai-collab-0.4.3.zip` was deleted.
- Tests: **39** (14 new for plan, checklist, risk merging and HTML rendering; all 25 old tests pass).

## Install

**Option A — Creator mode (recommended)**

```
plugin_manager
  action: install_bundle
  target: <absolute path to this package>
```

**Option B — CLI**

```powershell
dsh plugin --profile desktop add "F:\path\to\dsh-ai-collab"
# then append "dsh-ai-collab" to dsh.profile.bundles in
#   %USERPROFILE%\.dsh\profiles\desktop\package.json
```

**Option C — local absolute path (legacy, not recommended)**

Older hosts accepted a raw absolute-path row in the profile patch. On current builds this
does not mount reliably; use the bundle install above. The patch form is kept only for
isolated debugging:

Add to `$DSH_HOME/profiles/desktop/cordis.patch.yml`:

```yaml
- insert:
    - id: ai-collab
      name: F:\path\to\dsh-ai-collab\index.js
      config:
        autoInit: true
```

Patch loading converts absolute paths to file URLs, so no pnpm install is needed. Remove the block to roll back.

Restart the app. The profile's sessions (the GUI uses `desktop`) then expose the tools below.

## Configuration

`config` keys are read as-is (**no `Config` schema yet**, so values are not type-checked); all keys optional:

| Key | Default | Meaning |
|---|---|---|
| `autoInit` | `false` | On `session/created`, run `ai-ensure` in the session cwd unless it is a temp/system directory: scaffold `.ai/`, refresh `AGENTS.md` and the board |
| `maxTail` | `10` | How many recent log records `ai_status` returns |
| `initScript` | packaged `ai-ensure.ps1` | Override the ensure script |

## Tools

| Tool | Does |
|---|---|
| `ai_status` | Reads `.ai/status.json` + the last N log records (start a session here) |
| `ai_log` | Appends one record to `.ai/log.jsonl`; rejects invalid enums, requires `issue` for `blocked`/`failed`; refreshes `status.json`, the sibling board, `TASKS.md` and `.ai/SESSION_BOOT.md` |
| `ai_check` | Validates every record: required fields, enums, timezone, monotonic `ts`, unique `id`; audits the §8 discipline list for drift |
| `ai_board` | Read-only roll-up of sibling projects' `.ai/status.json` |
| `ai_init` | Ensures the workspace: scaffold if missing, refresh stale `.ai/`/`AGENTS.md`, refresh stale board (idempotent) |
| `ai_discipline` | Lists, adds, enables, disables and removes project disciplines; migrates/toggles the global discipline modules in `$DSH_HOME` |
| `ai_handoff` | Reads or rewrites the cross-session handoff packet (`.ai/SESSION_BOOT.md`) and returns an inheritance prompt |

## What `ai_init` creates

```
<project root>
├─ AGENTS.md              ← only visible file (facts + discipline pointer)
└─ .ai\
   ├─ llm.ps1, llm.cmd    ← CLI: status / tail / add / check / entries / archive / board / doctor
   ├─ log.jsonl           ← append-only, UTF-8 no BOM, LF
   ├─ status.json         ← current state (overwritten, `rev` increments)
   ├─ SESSION_BOOT.md     ← cross-session handoff packet (regenerated on demand)
   ├─ disciplines\        ← project discipline registry + rules\*.md
   ├─ LOG_FORMAT.md, SECURITY.md, schema\log.schema.json
   ├─ changelog\          ← version-level docs + patch engine
   ├─ entries\            ← forwarding-file masters (publish on demand)
   └─ _archive\
```

Record shape (one JSON object per line):

```json
{"id":"...","ts":"2026-11-04T17:10:00+08:00","tool":"claude-code","actor":"ai",
 "action":"fix","status":"ok","summary":"what changed + result",
 "files_modified":["src/a.c"],"verification":"rebuild 0/0, Code=78106"}
```

`status` ∈ `ok|partial|blocked|todo|failed`; `action` ∈ `task_start|task_done|fix|diagnosis|build|commit|doc|review|rollback|correction|maintenance|handoff`.

## Updating (after install)

The bundle is an npm package mounted into a profile. The Host loads it at boot and ships no HMR/watcher, so **code changes take effect only after a restart**.

1. Bump `version` in `package.json` (e.g. `0.2.0` → `0.2.1`) so you can tell what is live.
2. Reinstall from the same path (or a new version): `dsh plugin --profile desktop add "F:\path\to\dsh-ai-collab"`, or run Creator-mode `install_bundle` again.
3. Restart the app. Every session in that profile then uses the new code on its next turn.
4. Existing projects keep their own copied `.ai/` files. The next `ai-ensure` (or an `ai_init` tool call) sees a changed framework hash and refreshes `.ai/` + `AGENTS.md` automatically; projects you never revisit stay on the old copy until then.
5. Global `$DSH_HOME/AGENTS.md` is independent of this bundle: editing it applies to the next request immediately, with no restart.

## Verifying an install

Two append-only files under `$DSH_HOME/logs` record what actually happened at boot:

```powershell
Get-Content "$DSH_HOME\logs\ai-collab-boot.log" -Tail 3     # version=… autoInit=… home=env|homedir
Get-Content "$DSH_HOME\logs\ai-collab-tools.log" -Tail 3   # tools=ai_status,… spec=file:///…/app.asar/…
```

- A fresh boot line means `apply()` ran in this process.
- A `tools=` line means all eight tools registered; `spec` shows where `@deepseek-ai/dsh-tools` was loaded from.
- `load-failed` / `register-failed` lines carry the exact resolution errors.

The plugin is mounted from outside `app.asar` (a `link:`/absolute path), so the bare `@deepseek-ai/dsh-tools` specifier is not resolvable; it is loaded from the host's real `app.asar` path instead (see `asarRoots()` in `index.js`). `DSH_HOME` is read from the host environment and may be absent when the app is launched from Explorer — the plugin then falls back to `~/.dsh` (`home=homedir`).

## `AGENTS.md` zones: generated vs project-owned

`AGENTS.md` is split into two marked zones:

```
<!-- dsh-ai-collab:generated:start -->   … template maintened (routing, permissions, commands) …
<!-- dsh-ai-collab:generated:end -->

<!-- dsh-ai-collab:user:start -->        … project facts, sampling data, analysis methods, decisions …
<!-- dsh-ai-collab:user:end -->
```

- `ai_log` (and `ai_init`/`ai-ensure`) refresh the task list (`TASKS.md`) whenever the workspace has `.ai/tasks-enabled`.
- Re-render replaces **only** the generated zone. The user zone (and anything outside both zones) is preserved **byte-for-byte**; `placeholders.json`, `log.jsonl` and `status.json` are never touched.
- A file **without** the zone markers is treated as project-owned and is never rewritten; the rendered reference goes to `.ai/AGENTS.generated.md`. This includes legacy single-line-marker files, which are frozen.
- Explicit migration only:
  - `-ForceAgents` — rebuild the generated zone and move the whole old file into the user zone (nothing deleted);
  - `-ResetAgents` — discard old content and write the template (destructive, explicit; the old file is backed up to `.ai/backups/` first).

## Disciplines: global modules and project rules

### Global (`$DSH_HOME`)

- `$DSH_HOME/AGENTS.md` stays the file DSH injects into every session. `ai_discipline` with
  `action:"global-migrate"` splits it into `$DSH_HOME/disciplines/g0.md … gN.md` plus
  `$DSH_HOME/disciplines/disciplines.json`, then rewrites `AGENTS.md` as **one marker line + the
  original text, byte-for-byte**. Nothing is deleted; a timestamped copy is written first.
- `global-list` / `global-enable` / `global-disable` / `global-add` / `global-remove` manage the
  modules. Every change re-renders `AGENTS.md` from the enabled modules only.
- Disabling a global module is real: the text disappears from the injected file. It cannot be
  overridden per project, because DSH injects the global file unconditionally.

### Project (`.ai/disciplines/`)

- Registry: `.ai/disciplines/disciplines.json`; rule bodies: `.ai/disciplines/rules/<id>.md`.
- `ai_discipline action:"add" | "enable" | "disable" | "remove"` edits the registry and re-renders
  the workspace. Section **§8** of `AGENTS.md` (generated zone) lists every global module (G0…,
  read-only) and every project rule (P-…). The body of each **enabled** project rule is inlined
  into §8, so it is part of the prompt of the project; a disabled rule keeps only its table row.
- `ai_check` audits §8 against the registry and reports drift: an enabled rule whose body is
  missing, a disabled rule still inlined, or a registry that cannot be read.
- Raw format is intentionally plain: any human can edit the registry or the rule files; the next
  `ai-ensure` / `install.ps1` render will pick them up.

## Safety

- The log is **append-only**; corrections are new records (`action:"correction"`), never edits.
- `autoInit` writes **only** into project-like working directories, never into `%TEMP%` or read-only trees.
- No credentials expected in the log; a `SECURITY.md` in `.ai/` describes where secrets go (`.ai/private/`).
- The scaffold is a normal PowerShell script you can read: `ai-init.ps1` → `install.ps1` → `template/.ai/`.
- **Task lists are rendered inside the plugin** (`lib/tasks.js`); the plugin never executes a
  workspace-provided `.ai/llm.ps1`, so cloning a hostile repository and logging cannot run its code.

## Concurrency and file protection

- `lib/atomic.js` writes to a same-directory temp file, `fsync`s and renames (retries on
  `EPERM`/`EBUSY`/`EACCES`), so a reader never sees a half-written `status.json`, `TASKS.md` or
  `SESSION_BOOT.md`.
- `lib/lock.js` is a cross-process lock (`openSync(path, 'wx')`), stale after 30 s, 15 s timeout.
  `ai_log` holds `.ai/.log.lock` across the append **and** the status update; `status.json`
  carries a `rev` that increments on each write.
- `TASKS.md` refresh holds `.ai/.tasks.lock`; `SESSION_BOOT.md` is written atomically.
- `template/.ai/llm.ps1` mirrors this in PowerShell: `Write-TextAtomic` (temp + `File.Replace`),
  `Enter-ProjectLock` / `Exit-ProjectLock` around `add`, `tasks`, `board` and `archive`; `archive`
  aborts if the log grew while it was copying.
- `install.ps1` writes `AGENTS.md` atomically and backs it up to
  `.ai/backups/AGENTS.<stamp>.md` (last 10) before any change.
- Boundaries: this is **cooperative** locking between this plugin and `.ai/llm.cmd`, not an
  OS-level guarantee. Editors that ignore the lock can still race. `initScript` is trusted
  configuration — never point it at untrusted code.

## Uninstall

1. Remove `dsh-ai-collab` from `dsh.profile.bundles` (or set `enabled: false` on its row) and restart.
2. Optionally delete the package from the profile (`dsh plugin --profile desktop remove dsh-ai-collab`).
3. Per-project `.ai/` folders are plain files; delete at will.

## Global discipline (user level)

The bundle ships tools and workspace scaffolding, not a user-level instruction file. Two ways to
get the mandatory "step 0" behaviour in every session:

- **Fresh machine**: copy [`AGENTS.global.template.md`](AGENTS.global.template.md) to
  `$DSH_HOME/AGENTS.md`.
- **Existing `AGENTS.md`**: call `ai_discipline` with `action:"global-migrate"`. It backs up the
  file, splits it into `$DSH_HOME/disciplines/gN.md` + `disciplines.json`, and rewrites
  `AGENTS.md` as a single marker plus the original text (byte-for-byte). Then use
  `global-disable` / `global-enable` to switch individual sections off or on.

## Known limitations

- Verified against the shipped `@deepseek-ai/dsh-tools` contract (`0.2.2`): parameters use the property-map DSL, `output.render` returns an array of content blocks, and the session workspace is resolved loosely through `ctx.get('workingDirectory', false)` with a `process.cwd()` fallback. Still run the preflight in your own DSH build if you modify these parts.
- `ai_init` / `autoInit` are **Windows-only** (packaged PowerShell 5.1); the bundle is declared
  `"os": ["win32"]` and macOS/Linux are not supported yet. On other platforms the scaffold tools
  return `unsupported-platform` instead of failing silently.
- Config values are normalised in-process (no schemastery `Config` yet); invalid values produce warnings in `$DSH_HOME/logs/ai-collab-config.log`.
- A legacy `AGENTS.md` without zone markers is frozen by design; migrate explicitly with `-ForceAgents` or `-ResetAgents`.
- Global discipline toggles rewrite `$DSH_HOME/AGENTS.md`. They only work after `global-migrate`
  has produced the marker + `disciplines/` directory; `global-enable` of a missing module is
  rejected. A global module cannot be disabled for one project only — DSH injects the file
  unconditionally.
- Section §8 of a project `AGENTS.md` is refreshed by `ai-ensure` / `install.ps1`; a rule added
  while no render runs appears after the next `ai_init`, `ai_discipline` change, or session start.
- The locking is cooperative (plugin + `.ai/llm.cmd`); external editors are not blocked.
- The forwarding files for Claude Code / Gemini CLI are only masters under `.ai/entries/`; publish them with `.ai\llm.cmd entries -Publish` when a tool needs auto-discovery.
- Publishing is not automated yet — see `PUBLISH.md`.
